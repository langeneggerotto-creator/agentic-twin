# Dream Draw / 🅾️♾️ Value Compass — MVP Product Specification v0.1.0-DRAFT

## Product Identity

**Dream Draw** is the user-facing application that helps a person make a dream, challenge or life direction visible and move toward it through one meaningful next action.

**🅾️♾️ Value Compass** is the underlying directional model: it ranks candidate next steps by fit, readiness, return and cost while preserving truth, agency and long-horizon purpose.

## MVP User Journey

```text
Dream Intake
→ Current-State Capture
→ Direction Mode Selection
→ Best Move / Why Now / Watch Out
→ Guide Mode + H0–H5 Horizon Bridge
→ Micro-Navigation Card Spec
→ Feedback Signal
→ JSON Evidence Export
```

## Intake Contract

| Field | Purpose |
|---|---|
| Dream / challenge / direction | The user’s stated desired movement |
| Why it matters | Purpose context |
| Time horizon | Today, days, quarter or years |
| Current state | Present evidence/experience |
| Capability | Usable current strength |
| Constraint | Main limiting condition |
| Energy | Low, steady or strong |
| Challenge preference | Gentle, balanced or stretch |

## Guidance Modes

| Mode | Trigger Pattern | Guide | Intended Direction |
|---|---|---|---|
| Direction | Drift, confusion, overwhelm | Nola — Begin | Clarify one useful step |
| Correction | Failure, error, wrong turn | Rowan — Break / Correct | Repair the highest-friction mismatch |
| Compounding | Plateau, slow growth, repetition | Sienna — Build | Protect repeatable progress |
| Transition | New direction or change | Zara — Explore | Test a reversible next route |
| Leverage | Systems, tools, automation, scale | Mira — Integrate | Build reusable structure |
| Becoming | Identity, values, purpose | Mira — Integrate | Act in alignment with chosen standards |

## MVP Engine Boundary

The current engine is deterministic keyword and field-completeness logic. Its `Compass Value` is a design score that helps compare output completeness and fit signals; it is **not** a validated outcome prediction.

## Evidence States

| Evidence State | Meaning |
|---|---|
| Built | Browser interface, record storage and export exist. |
| Proposed | Direction/recommendation generated by design rules. |
| User Signal | User marks helped, reframe or not useful. |
| Not Proven | Behavior change, retention, transfer and life benefit are not yet measured. |

## Excluded Until Later Gate

- Autonomous life decisions.
- Covert persuasion or psychological manipulation.
- False personalization or claims the app “knows” the user.
- Live account/profile storage.
- Live AI recommendations without controlled evaluation.
- Photorealistic avatar claims of identity or readiness knowledge.
- Outcome or learning acceleration claims without evidence.

## Pilot Gate

**PILOT-DD-001:** Otto enters one real current dream or project direction, receives one recommendation, records feedback and exports the JSON result.

Success at this stage means only:

1. the app works end-to-end locally;
2. the recommendation is understandable;
3. the user can reject or redirect it;
4. the evidence record is exported correctly.
