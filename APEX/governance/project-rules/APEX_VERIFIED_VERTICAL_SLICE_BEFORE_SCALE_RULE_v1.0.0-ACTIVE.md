# APEX Verified Vertical Slice Before Scale Rule v1.0.0 — ACTIVE
## `🧪✅ → 📊⏩ → ♾️🔁`

## Decision

For all APEX / O∞ / PRISM modules, `APEX 1M / 🧪Ⓥ1M🅾️♾️💯` is no longer an automatic first execution mode for an undefined or unproven build scope.

The active execution default is:

```text
One verified vertical slice first
→ measure cycle time, quality, evidence completeness and human control
→ scale only the portions that demonstrate beneficial acceleration
→ continue bounded convergence only while proof and control remain intact
```

## Purpose

Accelerate real development rather than increase speculative iteration volume. High iteration counts are allowed only after a small working slice establishes measurable acceptance criteria and a safe repair/retest loop.

## Governing Rule

```text
Scale is earned by verified reduction in delivery friction
without reduced evidence quality, truth integrity, reversibility or human control.
```

## Application Across Modules

| Module Type | Required First Slice | May Scale After |
|---|---|---|
| Platform / Foundry | One task becomes one tested repository change and one visible status update | PR/test/evidence flow is verified |
| APEX Mirror | Dashboard reads real module-state records and exposes proof/holds | Data freshness and truth-state labels validate |
| Centralized Analytics / Data Governance | One accountable deliverable is registered with owner, evidence and gate | Named ownership and approval pathway exist |
| Learning Center | One real baseline/practice/retention/transfer pilot record | Measured evidence supports improvement |
| GitHub Auto-Capture | One eligible artifact submits, validates and is retrievable | Capture receipt and validation result exist |
| Visual / Media Modules | One visual is truth-labelled and bound to a verified data/spec source | Provenance and media-capture boundaries pass |
| GPU / Compute Modules | One measured bottleneck workload is benchmarked | Acceleration benefit is measured against cost/risk |

## Measurement Gate

Before scaling iteration volume, the vertical slice must record:

| Metric | Required Question |
|---|---|
| Cycle Time | Did the method reduce time from ready task to tested output? |
| Quality | Did acceptance tests pass without hiding defects? |
| Evidence Completeness | Is the result traceable to artifacts, tests and status records? |
| Human Understanding & Control | Can the operator understand, stop, redirect and reverse the change? |
| Risk / Holds | Did any privacy, safety, promotion or dependency gate activate? |
| Reuse Potential | Can the validated mechanism be safely reused elsewhere? |

## C∞ / APEX 1M Use After the First Slice

`C∞` and higher iteration depths remain available, but only for a declared bounded scope with valid metrics.

```text
No working slice → no scale claim.
No meaningful metric → no convergence claim.
No evidence → no promotion claim.
No human control → no autonomous expansion.
```
