## 6. Autonomy Scale Separation

The Safe Autonomy Charter scale is integrated as an execution-governance scale, not as a replacement for capability maturity, build-stage maturity, evidence maturity or physical deployment authority.

| Scale | Meaning | Rule |
|---|---|---|
| `SA0` | Observe, record, explain, recommend only | Permitted for safe non-sensitive scope |
| `SA1` | Propose, simulate, test, stage artifacts | Permitted for reversible local/software work with logging |
| `SA2` | Conditional bounded software execution under pre-approved controls | Target default only after gates, audit and rollback exist |
| `SA3` | Consequential action or expanded authority | Explicit human approval and verified evidence required |

| Authority Domain | Current Boundary |
|---|---|
| Software prototype/dry-run execution | May be tested within bounded authorized scope |
| GitHub safe-text artifact capture | Eligible on governed branch after screening and verification |
| Physical action, fabrication, movement or load testing | Locked unless separately authorized and safety gated |
| Real-person identity media or publication | Consent/provenance gated |

## 8. Safe Autonomy Interrupt Rules

The OS may proceed without interruption for reversible documentation, schemas, local tests, manifests, dashboard prototypes, non-sensitive artifact preparation and bounded scoring.

It must stop and request human decision for physical action, deployment, publication, credentials/secrets, sensitive data, irreversible destruction, financial commitments, medical claims, real-person likeness publication or any action exceeding evidence and authority.
